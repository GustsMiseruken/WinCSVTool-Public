# WinCSVTool 0.0.9

Windows 用の、巨大な CSV を編集・分析するためのポータブルアプリです。Excel（`.xlsx`）の読み込み・保存と、SQL を含む CLI 操作にも対応しています。
CSV を一度ディスク上の SQLite 作業データベースに取り込み、表は設定した行数ずつ表示します（既定は 512 行）。
全行をメモリに展開せず、2 コア・16 GB 未満の環境で数 GB・数百万～数千万行を扱うことを設計目標にしています。
初回の読み込み、ソート、統計、SQL は全データを走査するため、ファイルサイズとディスク速度に応じて時間がかかります。

この説明書はバージョン **0.0.9** を対象とします。

## 起動

1. ポータブルフォルダーを任意の場所へ展開します。
2. `WinCSVTool.exe` を起動します。.NET、Excel、データベースの別途インストールは不要です。
3. CSV または XLSX をウィンドウへドラッグするか、［開く］を押します。複数ファイルは上部のタブになります。XLSX の各シートは画面下部のタブで切り替えます。

コマンドラインでは同梱の `WinCSVTool.Cli.exe` を使います。IP 解析には同梱の `data/ip/` が必要なため、EXE だけを移さず、ポータブルフォルダー全体を展開してください。

対象は Windows x64 です。Windows 11など、[.NET 10のサポート対象OS](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)を使用してください。通常ユーザー権限で利用できます。
作業データは既定では Windows の一時フォルダー `%TEMP%\WinCSVTool\session-*` に作成します。［環境設定］で保存先を変更できます。
正常終了時にそのセッションの作業データを削除します。CSV の変更を残すには明示的に保存してください。
単一 EXE に含まれるネイティブライブラリは .NET の仕組みによりユーザーの一時領域へ展開されるため、一時領域への書き込み権限が必要です。

元の CSV、作業 DB、ソート用の索引、保存時の一時ファイルに空きディスクが必要です。
まず元 CSV の **2～4 倍程度**の空き容量を目安にしてください。これは見積もりで、短いセルが非常に多い表や複数の索引では超える場合があります。
USB メモリーから起動できますが、大容量ファイルの作業領域は高速なローカル SSD が適しています。
アプリの CSV 処理はローカルで行われます。

## 最小操作例

- CSV: ［開く］でファイルを選び、セルを編集して［保存］します。`000123` の先頭ゼロは保持します。
- Excel: XLSXを開き、下部のシートタブで切り替えます。保存はセル値のエクスポートです。数式・書式・グラフは保持しないため、別名保存を推奨します。
- SQL: ［SQL分析］で `SELECT * FROM t1 LIMIT 10` を実行します。表名はSQL画面の一覧から挿入できます。
- CLI: `WinCSVTool.Cli.exe view --input sample.csv --out copy.csv` でCSVを保存します。詳しいオプションは `WinCSVTool.Cli.exe help` を参照してください。

カラーテーマは［ライト］［ダーク］［システム設定に合わせる］から選べます。フォントは表とセル編集・SQLで別々に指定できます。
ダーク表示は表・SQLエディター・スクロールバーにも適用します。環境設定の入力欄とボタンの高さを揃え、ラベルの背景や罫線、適用・保存ボタンは控えめな配色にしています。
読み込み・保存の設定は新たに開くファイルや新規CSVの初期値です。すでに開いているCSVの文字コード、区切り文字、ヘッダー設定は変更せず、そのファイルの保存画面に引き継ぎます。

**画面右下の −／スライダー／＋／倍率表示**で、表・セル内容・SQLの表示倍率を **50～200%** に変更できます。
倍率表示を押すと 50・75・100・125・150・175・200% を選択できます。［表示］メニューや Ctrl++ / Ctrl+- で拡大・縮小し、Ctrl+0 で 100% に戻せます。
**Ctrl + マウスホイール**でも倍率を10%ずつ変更できます。［フォントと表示］の［Ctrl + マウスホイールで表示倍率を変更する］で有効・無効を選択できます（既定は有効）。
キーボードショートカットは環境設定で変更できます。操作を選んでキーを押し、重複がないことを確認して保存します。Ctrl / Alt との組み合わせ、またはファンクションキーを使用できます。

設定は **`WinCSVTool.exe` と同じフォルダーの `.local/settings.json`** に保存します。ポータブルフォルダーを移すと設定も持ち運べます。設定を保存するには、そのフォルダーへの書き込み権限が必要です。
配布ZIPには個人の設定ファイルを含めません。環境設定・倍率・ウィンドウ情報の保存時に自動作成します。

## ファイルの情報

CSVのタブを選び、［ファイル］→［ファイルの情報…］または Alt+Enter でプロパティを開きます。
ファイルの場所・サイズ・更新日時、文字コード、区切り文字、ヘッダーの有無、現在の行数・列数、編集状態、SQLのテーブル名、作業キャッシュの場所・サイズを確認できます。

## 開くときの設定

［ファイル］→［CSV / Excelを開く…］でファイルを選択します。CSV では次を指定できます。

| 設定 | 内容 |
|---|---|
| 文字コード | 自動判定、UTF-8、Shift_JIS（Windows-31J / CP932）、EUC-JP、UTF-16 LE / BE |
| 区切り文字 | カンマ、タブ（TSV）、セミコロン |
| 先頭レコードをヘッダーとして扱う | ヘッダーがないファイルではチェックを外す。列名は `Column1` などになります |

自動判定は BOM と先頭 64 KiB のバイト列を利用する推定です。曖昧な日本語文字コードを必ず区別できるものではありません。
文字化けした場合は［ファイル］→［文字コードを変更して開き直す］で明示指定します。
開き直すと未保存の変更は引き継がれません。変更がある場合は確認が表示されます。

セルは文字列として保存します。`000123` の先頭ゼロ、長い数値文字列、空欄を勝手に数値へ変換しません。
ダブルクォートで囲んだカンマ、改行、`""` によるクォートを扱えます。
列数が足りない行は空欄で補い、列数が多すぎる行や不正な引用符はエラーにします。
読み込みエラーや中断時には、そのファイルの部分的な取り込みを取り消します。

## Excelブック（XLSX）

［CSV / Excelを開く…］で `.xlsx` を選ぶと、各シートの先頭行をヘッダーにするか確認してから、ブックの全ワークシートを取り込みます。ブックは上部に1つのファイルタブとして表示し、各シートは画面下部のタブで切り替えます。ヘッダーがない場合は先頭行をデータとして保持します。

［保存］で保存先を `.xlsx` にすると、選択中のブックの全シートを保存します。CSV のタブからはその表を1シートとして保存できます。複数の CSV や開いている表をまとめるには、［ファイル］→［複数の表をExcelブックに保存…］を開き、保存する表とヘッダーの有無を選びます。選択した表ごとに1シートを作成します。

セルの値を対象にします。保存候補には `-values.xlsx` を付け、書式や数式が失われることと保存範囲を確認します。既存XLSXへの保存では追加の確認を行います。CLIでは既存XLSXへの出力に `--allow-lossy-xlsx-overwrite` が必要です。

数式はファイル内に保存済みの計算結果を読み込み、再計算しません。計算結果が保存されていない数式は空欄になります。保存する XLSX のセルは文字列なので、`000123` や `=SUM(A1:A2)` といった文字列をそのまま保持します。元の数式、セルの書式、色、結合セル、グラフなどは保持しません。数値・日時の表示も Excel と完全には一致しません。

| 項目 | 上限 |
|---|---|
| XLSX読み込み | 1シートあたり1,999列、1ブックあたり1,024シート |
| XLSX保存 | 1シートあたり1,048,576行（ヘッダーを含む）、16,384列、1ブックあたり1,024シート |
| セルの文字数 | 32,767文字（.NETのUTF-16単位） |

保存時の形式上限が16,384列でも、本アプリの作業テーブルには別途 SQLite の列数制約があります。上限を超える行数の CSV は複数の表に分けるか CSV のまま保存してください。シートの自動分割は行いません。旧形式 `.xls`、マクロ付き `.xlsm`、暗号化ブック、外部シートやグラフシートの取り込みには対応していません。

## 表の操作と編集

- 起動直後から列記号・行番号の付いた表を表示し、CSV を開いた後も右側・下側の余白にセルの罫線が続きます。余白は表示専用で、CSV の行・列や保存データには追加されません。
- ファイルのタブ、よく使う操作のツールバー、セルの全文エディターを同じ画面にまとめています。SQL・検索・デコードの窓も共通の配色で表示します。
- タブをクリックしてファイルを切り替えます。タブの ×・マウス中ボタンでそのタブを閉じます。Ctrl+W、［ファイル］→［タブを閉じる］は現在のタブを閉じます。
- 表上部の先頭・前・次・末尾の矢印ボタンでページを移動します。既定は 512 行で、環境設定で変更できます。
- ［行へ移動］に 1 から始まる行番号を入力すると、その行を含むページへ移動します。フィルター中は表示結果の行番号です。
- セルをダブルクリックすると編集できます。長い値や改行を含む値は、画面下部の全文エディターで編集して［セルに反映］を押します。
- ツールバーの［折り返し］または［表示］→［セルの折り返し切替］で表の折り返しを切り替えます。表示領域を超える全文は下部エディターで確認できます。
- マウスのドラッグや Ctrl / Shift を使ってセル範囲を選択できます。コピーは Ctrl+C です。
- 列見出しの上段にある A・B・C… をクリックすると、その列の現在のページ内のセルを選択します。下段のヘッダー名をクリックすると、表全体の昇順・降順を切り替えます。
- 選択した列を右クリックすると、左・右への列挿入、列名の変更、選択列の削除ができます。複数列の削除にも対応し、最後の1列は残します。列の挿入・削除では残る列のソート・フィルターを引き継ぎ、削除した列の条件だけを外します。
- ［編集］には行の末尾追加、選択行の削除、列の追加・名前変更・削除があります。行削除では選択セルを含む行が対象です。

タブの青い点は未保存の変更を示します。直前の対応操作を1段階取り消せます。やり直し、複数セルへの貼り付け、任意位置への行挿入、列の移動には対応していません。
表のセル選択は現在のページ内です。全体に対する処理は対応するダイアログの全体指定、フィルター、SQL を利用してください。

## 列の型、ソート、フィルター

セルを選び、［列の型］から `Auto`（自動）、`Text`（文字列）、`Number`（数値）、`Timestamp`（日時）、`Boolean`（真偽値）を指定します。
型は比較方法を指定するもので、元の文字列を書き換えません。識別子や商品コードには `Text` が適しています。
`Auto` は値ごとに数値、日時、文字列の順で比較を試みます。列の値が混在して意図どおりに並ばない場合は型を明示してください。
型の設定はセッション内で有効です。CSV には型情報がないため、再度開いた際は `Auto` に戻ります。

列見出しの下段（ヘッダー名）のクリックで昇順・降順を切り替えます。上段の列記号は列の選択です。
［ソート / フィルター］では複数のソートキーを優先順位順に追加でき、フィルター条件も追加できます。
フィルターは「含む」「等しい」「等しくない」「前方一致」「後方一致」「より大きい」「より小さい」「空」「空でない」「正規表現」です。
複数の条件は AND（すべて満たす）で適用されます。通常の文字列検索は大文字・小文字を区別しません。
等値比較と文字列ソートは SQLite の `NOCASE` に従い、主に ASCII 英字の大文字・小文字を同一視します。日本語の読み順のソートには対応していません。
条件の一覧から項目を削除して調整し、［適用］で表全体へ適用します。
［データ］→［ソートとフィルターを解除］で元の行順の全体表示へ戻れます。

ソートとフィルターは表示を変えます。通常の保存は元の行順の全行を保存し、［表示結果を保存］は現在の条件と並び順をCSVまたはXLSXに保存します。

## 検索と置換

［検索 / 置換］または Ctrl+F で開きます。
文字列検索または .NET 正規表現を選べ、現在の列か全列を対象にできます。
検索・一括置換は現在のソートとフィルターに対応します。
正規表現の置換では `$1` などのキャプチャを利用できます。例: `ID-(\d+)` を `No.$1` に置換します。
極端に時間のかかる正規表現には 1 セルあたり 1 秒のタイムアウトを設けています。
一括置換は予定変更件数と短い例を確認してから実行します。エラー・中断時には全変更を取り消し、成功後は直前の1操作を［取り消す］で戻せます。

## URL / Base64 デコード

デコードするセル範囲を選択し、［デコード］を押します。
方式（URL または Base64）、デコードしたバイト列の文字コードを指定し、プレビューを確認して適用します。
URL の `+` を空白として扱うかを切り替えられます。`%2B` は `+` に変換されます。
例: `%E6%97%A5%E6%9C%AC%E8%AA%9E` → `日本語`、`MDAwMQ==` → `0001`。

通常は、選択されたセルを含む行 × 選択された列の組み合わせが対象です。
［選択列の全行に適用］を選ぶと、現在のフィルターに一致する全行の選択列に適用します。
空欄は無視します。不正な `%HH`、Base64、指定文字コードでは復号できないバイト列がある場合、変更をすべて取り消して該当行・列を表示します。
0.0.9 の対応方式は URL と Base64 です。一括デコードのエラーには、処理開始時の対象順による1始まりの表示データ行と列を示します。ソート・フィルター・選択した行を反映した順序です。セル内の文字位置は別に示し、失敗時は変更をすべて取り消します。

## ログ解析：オフラインIP・ASN

ツールバーの［ログ解析］、または［ログ解析］→［IP・ASNを解析…］で専用の機能タブを開きます。

- ［IPアドレス］に IPv4 / IPv6 を入力して［IPを調べる］を押すと、国・地域、国コード、IP区分、ASN、AS組織・事業者を表示します。
- ［AS番号］に `AS15169` または `15169` のように入力し、［ASNを調べる］で記録された事業者を確認できます。
- ［参照データの詳細］で、基準日、元データの生成日時、出典、ライセンス、SHA-256を確認できます。
- ［解析対象の表］と［IPアドレスの列］を選び、［追加する列］の横並びのチェック項目から必要な列を選んで［選択した列を追加］を押します。フィルターやページ表示に関係なく**元の表の全行**が対象です。すべてのチェックを外すと追加ボタンは無効になります。
- 各項目は、淡いチェックの印・列名・情報アイコンの順に並びます。列名をクリックしても選択を切り替えられます。右端の情報アイコンをクリックすると、その列の説明をポップアップで表示します。マウスオーバーでは説明を表示しません。ポップアップは外側のクリックまたはEscで閉じます。

選べる項目は、国・地域、国コード、IP区分、ASN、AS組織・事業者、データ基準日、出典、ライセンスの8種類です。初期状態はすべて選択されています。チェックした列だけを実際の表に追加し、未選択の列は作成しません。元のIP列や他のセル値は保持します。同名の列がある場合はSQL用の列名を調整します。処理失敗・中断時は途中の列追加を取り消します。基準日・出典・ライセンスは、列に追加しなくても［参照データの詳細］で確認できます。結果を残すにはCSVまたはXLSXへ保存してください。

国・地域名の言語は［オプション］→［環境設定…］→［一般］の［ログ解析の国・地域名の表示言語］で［日本語］または［English］を選択します。変更はその後の解析に適用し、既に追加した列は書き換えません。

判定は同梱の **DB-IP Lite 2026-10-01版**を使用し、インターネットへのアクセス、DNS照会、自動更新は行いません。プライベートIP、ループバック、リンクローカル、共有CGNAT、文書用、マルチキャストなどは区分を明示し、国や事業者を割り当てません。不正なIPや参照データにないIP・ASNは不明として表示します。

国・地域はネットワークの推定情報であり、利用者の国籍や現在地を示すものではありません。AS組織は参照データに記録されたネットワーク運用者で、利用者の契約先や法的所有者と一致するとは限りません。
IP Geolocation and ASN data by [DB-IP.com](https://db-ip.com/)。データは [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) で再配布しています。公式の[国・地域データ](https://db-ip.com/db/download/ip-to-country-lite)と[ASNデータ](https://db-ip.com/db/download/ip-to-asn-lite)を利用しています。基準日、元データの生成日時、出典、SHA-256 は同梱の `data/ip/metadata.json`、ライセンスと変換内容は `data/ip/README.md` で確認できます。

## 統計

［統計］で［選択範囲］または［現在のフィルター結果の全行・全列］を選びます。
選択範囲は選択した行 × 選択列です。飛び飛びの行選択では、間の未選択行を含めません。
並び替えやフィルターの列を編集した直後でも、選択した行そのものを集計します。全行の対象を選ぶと現在のフィルター条件を適用します。

| 対象 | 取得できる値 |
|---|---|
| 共通・文字列 | 行数、空欄・非空欄数、異なる値の数、最頻値と件数、文字数の最小・最大・平均、文字列としての最小・最大 |
| 数値として解釈できる値 | 件数、非数値件数、合計、平均、最小・最大、中央値、四分位数、母集団・標本の分散と標準偏差 |
| 日時型 | 日時として解釈できる件数、非日時件数、最小・最大日時（UTC） |
| 真偽値型 | 真・偽・非真偽値の件数、真の割合 |

数値の詳細統計は `Auto` / `Number` の列で表示します。有限の数値だけを対象にし、空欄や非数値を 0 として扱いません。
小数点は `.`、指数表記は利用可能です。桁区切り付きの文字列は数値として扱いません。
標本分散・標本標準偏差は 2 件以上で計算します。四分位数は線形補間によります。
最頻値・異なる値の数では空欄を除外します。同率の最頻値がある場合は説明行が付きます。
文字数は .NET の UTF-16 単位です。絵文字などは画面上の 1 文字が 2 単位以上になる場合があります。
数値は倍精度浮動小数点で計算するため、会計用途などの厳密な十進小数計算には誤差を考慮してください。

## SQL 分析

［SQL分析］または Ctrl+Q でSQLパネルを開きます。［実行］または Ctrl+Enter でクエリを実行します。
表示位置は［環境設定］→［ウィンドウとパネル］で［別ウィンドウ］［CSVの右側に並べる］［CSVの下側に並べる］［同じウィンドウのタブ］から選べます。SQLパネルの［表示位置］からも変更できます。
右側・下側に並べた場合は、境界線をドラッグしてCSVとSQLの表示領域を調整できます。配置と分割比率は設定に保存されます。
スキーマ欄に各タブのテーブル名（`t1`、`t2` …）と SQL 用の列名が表示されます。
ヘッダーの重複・空欄・予約名は SQL 用に調整されるため、スキーマの名前を使用してください。CSV 保存時の元ヘッダーは保持します。
スキーマ欄のテーブル名・列名はダブルクリック、または選択して Enter でカーソル位置へ挿入できます。挿入できる名前は控えめな下線と色で示し、空白や記号を含む名前も使えるようSQL識別子として引用します。
SQLエディターはキーワード、文字列、コメント、数値、識別子、関数を色分けして表示します。

```sql
-- まず内容を確認
SELECT * FROM t1 LIMIT 20;

-- グループ別の合計。CSV の値は文字列なので数値へ明示変換
SELECT "分類", SUM(CAST("金額" AS REAL)) AS "合計"
FROM t1
GROUP BY "分類"
ORDER BY "合計" DESC;

-- 2つのタブをIDで結合
SELECT a."ID", a."名称", b."金額"
FROM t1 AS a
JOIN t2 AS b ON a."ID" = b."ID";
```

SQLite の SELECT / WITH クエリを 1 文ずつ実行できます。DELETE / UPDATE / DROP / ATTACH / PRAGMA などは実行できません。
SQL の対象は全行です。表の表示フィルターは SQL には自動適用されないため、必要な条件は `WHERE` に記述します。
実行結果の画面表示は最大 1,000 行です。非常に大きな値がある場合はメモリ保護のため、これより少ない行でプレビューを止める場合があります。
［全結果をCSVに保存］と［結果を新規CSVタブにする］はプレビュー上限に関係なくクエリ結果全体を処理します。
CSV 出力は文字コード、区切り文字、ヘッダーの有無を指定できます。
`WCT_NUMBER(列)` は有限の数値に変換し、解釈できない値を SQL の `NULL` にします。`WCT_TIMESTAMP(列)`、`WCT_BOOLEAN(列)`、`列 REGEXP '式'` も利用できます。
実行時の構文エラーは表示します。入力中の構文チェック・補完は未実装です。

## 保存と中断

［保存］または Ctrl+S で保存先とファイル形式を選びます。CSVでは文字コード、区切り文字、ヘッダー、BOMの有無も指定できます。XLSXにはCSVの文字コード・区切り文字の設定を適用しません。
保存時に表現できない文字は置換せずにエラーにします。例えば Shift_JIS へ保存できない絵文字がある場合は UTF-8 などへ変更してください。
完全に出力できたことを確認してから保存先を置き換えるため、処理失敗時に既存ファイルを途中の内容で上書きしません。
保存先と同じフォルダーに一時ファイル分の空き容量が必要です。
処理中は画面下部の［中断］を利用できます。読み込み・一括変換・保存では変更途中の内容を確定しません。
CSV を再出力するため、引用符の付け方や改行コードは正規化される場合があります。セル値とヘッダーの内容を保持する方式で、元ファイルのバイト単位の保持ではありません。

## コマンドライン（CLI）

PowerShellやコマンドプロンプトから同梱の `WinCSVTool.Cli.exe` を使えます。GUIを起動せず、CSV / XLSX の変換、SQL、ソート・フィルター、検索・置換、デコード、統計、IP・ASN解析を実行できます。

```powershell
.\WinCSVTool.Cli.exe help
.\WinCSVTool.Cli.exe version
```

入力は `--input ファイル` で指定します。列はヘッダー名、SQL用の列名、または `#1` のように1から始まる列番号で選べます。PowerShellの列番号指定は `--column '#1'` のように引用符で囲みます。以下はPowerShellの例です。空白を含むパスや値も引用符で囲んでください。

```powershell
# 複数CSVを1つのExcelブックのシートにする
.\WinCSVTool.Cli.exe convert --input access.csv --input users.csv --out logs.xlsx

# ブックの表情報をJSONで確認し、指定シートをCSVへ保存
.\WinCSVTool.Cli.exe info --input logs.xlsx
.\WinCSVTool.Cli.exe convert --input logs.xlsx --sheet users --out users.csv

# 複数入力にSQL名を付けて結合し、全結果をCSVへ保存
.\WinCSVTool.Cli.exe sql --input logs=access.csv --input users=users.csv --query 'SELECT logs.ID, users.name FROM logs JOIN users ON logs.ID = users.ID' --out joined.csv

# UTF-8のSQLファイルを実行。--previewは上限付きJSONプレビュー
.\WinCSVTool.Cli.exe sql --input logs=access.csv --query-file query.sql --out result.csv
.\WinCSVTool.Cli.exe sql --input logs=access.csv --query 'SELECT * FROM logs' --preview 1000

# IP解析の8列を追加して保存／単独のIPやASNを確認
.\WinCSVTool.Cli.exe ip --input access.csv --column ip --country-language ja --out enriched.csv
.\WinCSVTool.Cli.exe ip-lookup --address 8.8.8.8 --country-language en
.\WinCSVTool.Cli.exe ip-lookup --asn AS15169
.\WinCSVTool.Cli.exe ip-data

# 統計、型を指定したソートとフィルター
.\WinCSVTool.Cli.exe stats --input access.csv --column bytes
.\WinCSVTool.Cli.exe view --input access.csv --sort bytes:desc --type bytes:Number --filter status:Equals:200 --out filtered.csv

# 正規表現検索・置換、URLデコード
.\WinCSVTool.Cli.exe find --input access.csv --column request --pattern '^GET' --regex
.\WinCSVTool.Cli.exe replace --input access.csv --column request --pattern 'old' --replacement 'new' --out replaced.csv
.\WinCSVTool.Cli.exe decode --input access.csv --column request --kind url --decoded-encoding utf-8 --out decoded.csv
```

| オプション | 内容 |
|---|---|
| `--encoding` / `--delimiter` / `--no-header` | CSV入力の文字コード、`comma` / `tab` / `semicolon`、ヘッダーなし |
| `--sheet` | XLSXのシート名または1から始まる番号。省略時は全シート |
| `--out` | 保存先。表の出力は拡張子 `.xlsx` ならExcelブック、それ以外ならCSV。複数表の保存はXLSXを指定 |
| `--output-encoding` / `--output-delimiter` / `--no-output-header` / `--bom` | CSV出力の文字コード、区切り文字、ヘッダーなし、BOM付き |
| `--query` / `--query-file` | SQLを直接指定するか、UTF-8ファイルから読む。どちらか1つを指定 |
| `--preview 1000` | SQLを上限付きJSONで出力。1～100,000行を指定でき、大きなセルがある場合は文字数上限で早く停止することがある |
| `--sort` / `--filter` / `--type` | `列:asc/desc`、`列:Equals:値`など、`列:Number/Text/Timestamp/Boolean/Auto`。繰り返し指定可能 |
| `--column` / `--regex` / `--start` | 対象列、正規表現、検索の開始位置（0から）。複数列指定はデコードで利用可能 |
| `--kind` / `--literal-plus` | デコード方式 `url` / `base64`。URLで `+` を空白へ変換せず保持する場合は `--literal-plus` |
| `--country-language` / `--ip-data` | 国・地域名の言語 `ja` / `en`、ローカルIP参照データのフォルダー |
| `--work-folder` / `--settings` | 作業データの保存先、既定値として読み込む設定JSONの場所 |

SQL入力に名前を付けない場合は `t1`、`t2` … を使います。XLSXを複数シートのまま名前付き入力すると、最初の表は指定名、続く表は `名前_2`、`名前_3` … になります。`info` で対応を確認できます。SQLはGUIと同じSELECT / WITHの読み取り専用です。
`--preview` を付けないSQL出力は結果全体をCSVまたはXLSXへ保存します。`--preview` と `--out` を併用した場合は、指定ファイルにJSONプレビューを保存します。
`convert` は複数表を扱えます。統計、検索・置換、デコード、IP列追加、表示条件による出力は1つの表が対象なので、必要に応じて `--sheet` で選択します。

出力先を省略すると、表・SQL結果は**全行をUTF-8 CSV**、情報・統計・検索結果・IP情報はJSONとして標準出力へ書きます。処理状況とエラーは標準エラー出力です。CLIは既定でEXEと同じフォルダーの `.local/settings.json` から作業先、国名言語、CSV入出力の既定値を読み、コマンド引数を優先します。設定ファイルへの書き込みは行いません。
`replace` と `decode` は変換開始時の対象行・並び順を保持して出力します。フィルター列の値を変更しても、対象行が出力から消えることはありません。内部管理用の行IDは通常のSQL結果や出力に含めません。

通常のCSV保存は値をそのまま保持します。Excel等で開く用途ではGUIの［表計算ソフトでの数式解釈を防ぐ］またはCLIの `--escape-spreadsheet-formulas` を明示選択できます。式として解釈され得る値にアポストロフィを付けるため、出力の値は変化します。式保護は別の出力として扱い、編集中の表の値・保存先・未保存状態を保持します。XLSXは引き続き文字列セルとして保存します。

Ctrl+Cで処理を中断できます。ファイル保存は完了してから保存先を置き換えます。標準出力への書き込みは途中まで出力されることがあります。終了コードは **0: 成功、1: 処理失敗、2: 引数エラー、130: 中断**です。

## ソースからビルド

ソースからのビルドには Windows x64 と `global.json` に指定した .NET SDK 10.0.402 が必要です。配布先に SDK / ランタイムは不要です。

```powershell
dotnet restore WinCSVTool.sln --locked-mode
dotnet build WinCSVTool.sln -c Release --no-restore
dotnet run --project src/WinCSVTool
```

ポータブル版を作成するには、リポジトリのルートで次を実行します。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/publish-portable.ps1
```

`artifacts/WinCSVTool-0.0.9-portable/` にGUI用 `WinCSVTool.exe`、CLI用 `WinCSVTool.Cli.exe`、`data/ip/`、README、第三者ライセンスを出力します。
同じ内容をまとめた `artifacts/WinCSVTool-0.0.9-win-x64-portable.zip` も作成します。
各EXEは自己完結型・単一ファイル・圧縮ありで作成し、**各100,000,000バイト未満**でなければパッケージ作成をエラーにします。IP参照データはEXEの外に同梱します。配布先に.NETやExcelなどの導入は不要です。
依存パッケージはロックファイルで固定し、ビルド時には推移依存を含む脆弱性監査を行います。既存の配布物は上書きしません。SHA-256一覧を同じ場所に生成します。コード署名を行う場合は `-SigningCertificateThumbprint` を指定します。証明書を指定しない場合は未署名です。
